# 08. 通知設計 — OneSignal「Keep Them Coming Back」戦略

> 賞の審査観点=「実装の質と安定性・UXへの付加価値・Journeys等の創造的活用」。育児アプリは通知の必然性が最も高いジャンルのひとつ。**「再訪促進」ではなく「家族の連携プレー」として設計する**のが勝ち筋。

## 統合方針(技術)

- OneSignal に KMP SDK はない(裏取り済)→ expect/actual で薄い `NotificationGateway` を切り、iOS(SPM: OneSignalFramework + OneSignalExtension/NSE)・Android(5.9.x)のネイティブSDKを統合。
- ユーザーIDは Supabase auth uid を external_id に設定。タグ: `baby_age_days`, `role`(mother/father...), `premium`, `voice_usage_rate`, `last_log_hours_ago`。

## 通知カタログ(すべて設定でオフ可・デフォルトは控えめ)

### 1. 連携プレー通知(このアプリならではの価値)
- パートナーが記録したら相手に静かに通知: 「🍼 ミルク80ml(パパが記録)」→ **「さっき飲んだ?」の夫婦の聞き合いを消す**。
- 交代要員向け「引き継ぎサマリ」: パートナーが帰宅する時間帯(学習 or 設定)に「今日ここまで: 授乳5回・最後は14:30右10分」。

### 2. リマインダー(押し付けない)
- 授乳間隔アラート: 前回から N 時間(ユーザー設定)で通知。**深夜は通知しない(赤ちゃんが寝てるのに起こす通知は禁忌)** — 時間帯サイレンスをデフォルトON。
- 「タイマー走りっぱなし」検知(90分)— `05` の仕様と連動。

### 3. Journeys(OneSignalの機能を「創造的に」使う部分)
- **新生児期オンボーディングJourney**(生後日数タグ駆動): D1「最初の記録おめでとう」→ D3「声だけで記録してみましょう(L2の使い方)」→ D7「今週のまとめ+パートナー招待提案」→ D14「トライアル終了前の正直な案内」。
- **卒業Journey**: 記録が30日途絶→「卒業おめでとう」+エクスポート案内(`07`の誠実さ戦略と連動)。解約導線を通知から1タップで。
- 賞の提出文では「push を減らすために Journey を使った(誤爆ゼロ設計)」という逆張りの物語を数値付きで語る(オプトアウト率・通知経由復帰率を計測)。

### 4. ローカル通知との使い分け
- タイマー系・時刻確定系はローカル通知(オフライン確実性)。サーバー起点(パートナー記録・Journey)のみOneSignal。この使い分け自体を提出文に書く(「安定性」の審査観点に対応)。
