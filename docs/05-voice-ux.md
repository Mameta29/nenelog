# 05. 音声UX仕様 — コマンド文法・対話フロー・TTS台本

> このドキュメントが本プロダクトの心臓。実装前にここを確定させ、変更は必ずここに反映する。

## 設計原則

1. **短い・確実・訂正可能**: 深夜の疲労状態で使う。コマンドは1〜3語。誤認識は1発話で取り消せる。
2. **応答は短く、確認は控えめに**: 毎回「〜を記録しました。よろしいですか?」は破綻する。破壊的でない操作は即実行+短い応答。取り消しで巻き戻す。
3. **静かな環境への配慮**: 赤ちゃんが寝ている部屋で使う。応答音量は3段階(通常/小声/ハプティクスのみ)。
4. **音声とタップは常に等価**: すべての音声操作に画面での代替手段がある(アクセシビリティの双方向性)。

## 音声レベルと起動経路(再掲+詳細)

| レベル | 起動 | リスニング | 応答 |
|---|---|---|---|
| L1 プッシュトゥトーク | ウィジェット/タイル/アプリ内ボタンをタップ | 1発話(〜10秒)で自動クローズ | TTS+画面 |
| L2 セッションモード | 授乳/寝かしつけセッション開始時に自動オン(設定可) | セッション中連続。画面オフ可(FGS/背景オーディオ) | TTS+ハプティクス |
| L3 Siri(iOSのみ) | "Hey Siri, <フレーズ>" | Siriが担当 | Siriが読み上げ(App Intents の dialog) |

- L2 の連続リスニングは**セッション中のみ**。常時ウェイクワードは実装しない(バッテリー・プライバシー・誤起動・審査リスクの4重回避)。
- TTS発話中はマイクを一時停止(エコー誤認識防止)。応答後300msで再開。

## コマンド文法(日本語)

### タイマー操作(L2/L3)
| 発話 | 動作 | TTS応答 |
|---|---|---|
| 「右」「右スタート」 | 右タイマー開始(走行中の左は自動停止・区間記録) | 「右、スタート」 |
| 「左」「左スタート」 | 同上(左) | 「左、スタート」 |
| 「交代」「チェンジ」 | 走行中と反対側に切替 | 「交代、左です」 |
| 「ストップ」「終わり」「ごちそうさま」 | セッション終了・記録保存 | 「おしまい。みぎ、10分。ひだり、8分を記録しました」 |
| 「一時停止」 | タイマー一時停止 | 「一時停止」 |
| 「再開」 | 再開 | 「再開します」 |

### 照会(voice-out の核)
| 発話 | TTS応答例 |
|---|---|
| 「今何分?」「どのくらい?」 | 「右side、12分です」 |
| 「前回は?」「前回の授乳は?」 | 「2時間15分前、左10分・右5分です」 |
| 「次は?」(どちらから) | 「前回は右で終わったので、左からがおすすめです」 |
| 「今日のまとめ」 | 「今日は授乳7回、ミルク合計160、うんち2回、おしっこ5回です」 |
| 「最後のうんちは?」 | 「今朝8時20分、5時間前です」 |

### 単発記録(L1/L2/L3)
| 発話 | 記録 | TTS応答 |
|---|---|---|
| 「ミルク80」 | ミルク80ml | 「ミルク80、記録しました」 |
| 「うんち」「うんち出た」 | うんち | 「うんち、記録しました」 |
| 「おしっこ」 | おしっこ | 「おしっこ、記録しました」 |
| 「両方」 | おしっこ+うんち | 「おしっことうんち、記録しました」 |
| 「寝た」「おやすみ」 | 睡眠開始 | 「おやすみなさい」 |
| 「起きた」 | 睡眠終了 | 「起きました。3時間20分寝ました」 |
| 「体温 36度8分」 | 体温36.8 | 「36.8度、記録しました」 |
| 「メモ 〜〜」 | 自由メモ(P1でAI構造化) | 「メモしました」 |

### 制御
| 発話 | 動作 |
|---|---|
| 「取り消し」「間違えた」 | 直前の記録/操作を取り消し →「取り消しました」 |
| 「静かに」 | 応答をハプティクスのみに →(バイブ2回) |
| 「声出して」 | TTS応答に戻す |
| 「終了」「もう聞かないで」 | リスニング終了 |

## コマンド文法(英語)

- Timer: "right" / "left" / "switch" / "stop" / "pause" / "resume"
- Query: "how long?" / "last feeding?" / "which side?" / "today's summary"
- Log: "bottle 80" / "poop" / "pee" / "both" / "asleep" / "awake" / "temperature 99.1" / "note ..."
- Control: "undo" / "quiet mode" / "voice on" / "end session"
- TTS応答は同じ構造で英語台本を用意(実装時に `strings` として日英対で管理)。

## 認識エンジン方針

- 画面表示・保存データでは「右」「左」を使うが、日本語TTS台本では誤読を避けるため
  「みぎ」「ひだり」と読み仮名を明示し、方向と時間の間に読点を入れる。
- Android API 33以降では固定コマンドを `EXTRA_BIASING_STRINGS` へ渡し、最上位候補だけでなく
  返却候補のうち固定文法に最初に一致したものを採用する。候補にない語を部分一致で拾わない。
- Androidが正しい途中候補を返した直後に最終結果なしの `ERROR_NO_MATCH` で終了した場合は、
  **その認識サイクルの最後の途中候補**が固定文法に完全一致するときだけ採用する。途中候補を
  到着時点では実行せず、過去の途中候補・部分一致・文中一致は採用しない。
- Android L2の1語形「右」「左」は音響的に曖昧なため、短縮エイリアスとしては残すが
  推奨発話にしない。暫定推奨だった「右スタート」「左スタート」も、9/1のPixel 8静音
  反復測定で各4/10に留まったため、リリース時の推奨発話には未確定とする。
- 音響的に長い候補A「みぎ/ひだりのおっぱい」と候補B「みぎ/ひだりで授乳」を診断専用で
  各5回比較したが、Aは右2/5・左5/5、Bは右3/5・左0/5と左右差が大きく、語彙変更だけでは
  解決しなかった。両候補は**製品文法・UI案内へ追加しない**。
- 製品の主コマンドは自然で意図も明確な「右スタート」「左スタート」を維持し、1語形
  「右」「左」は短縮エイリアスとして残す。今後は発話を不自然に変えるのではなく、Androidの
  固定コマンド認識方式を改善する。実測された誤変換語を安易なエイリアスにせず、背景会話に
  よる誤作動を避けながら左右各9/10以上を目標とする。
- Androidの比較候補として、Vosk日本語smallモデルを使う完全オフライン固定文法を診断した。
  製品と同じ「右スタート」「左スタート」でPixel 8静音20発話を測り、右9/10・左7/10、
  全体16/20だった。失敗4件はいずれも反対側への誤認識ではなく、`[unk]`・無認識・方向語欠落
  だった。認識を700ms先に起動し、振動後に発話する条件で再測定すると、右9/10・左10/10、
  全体19/20(95%)となり、静音目標を達成した。唯一の失敗も方向語欠落で逆方向誤実行は0件。
  タップ試験では認識起動完了を明示し、本番の連続待受では起動完了後だけ待受状態を表示する。
  同じ条件で端末を約50cm離した小声10発話は、右2/5・左4/5、全体6/10に低下した。
  失敗4件はすべて方向語だけが欠け、逆方向誤実行は0件。Voskの本番採用は、入力レベル補正後の
  小声・生活音と48MBモデルの配布容量を確認してから確定する。AudioRecordの16-bit PCMを
  Vosk投入前に3倍補正すると、同条件で右4/5・左5/5、全体9/10へ改善し、クリッピングは
  全10回0‰だった。5倍補正は右3/5・左4/5、全体7/10へ低下したため棄却し、3倍を現時点の
  最有力とする。Android実機評価ビルドでは、日本語L2の実タイマー画面にVosk固定文法+3倍入力を
  接続し、モデルが利用できない場合と英語ではOS SpeechRecognizerへ戻す。製品採用の最終判断は
  実画面の左右切替・停止、生活音、背景会話、48MBモデル容量の確認後に行う。

- **一次: OSネイティブのオンデバイス認識**(iOS: SFSpeechRecognizer系 / Android: SpeechRecognizer)。理由: 無料・低遅延・オフライン・プライバシー(育児データ+常時マイクという性質上、音声をサーバーに送らないことを明言できる = Peace Prize/ストア審査でも効く)。
- 認識結果に対しては**キーワードスポッティング**(固定文法とのファジーマッチ)で解釈する。LLMは使わない(決定的・オフライン・高速)。
- 「メモ 〜」だけは自由文をそのまま保存し、P1でオンライン時にAI構造化(`07`参照。Claude Haiku系をバックエンド経由で使用。実装時は `claude-api` スキルで最新モデル・料金を確認すること)。
- 信頼度が閾値未満 → ハプティクス1回+「もう一度お願いします」(2回失敗で「画面からも入力できます」+通知に記録候補を残す)。

## エッジケース仕様

- **重複開始**: 走行中と同じ側の「右/左スタート」は冪等なno-opとし、通常どおり
  「右/左、スタート」と短く応答する。反対側なら現在区間を閉じて即座に切り替える。
- **停止中のストップ**: 記録は作らず、日本語「タイマーは動いていません」/
  英語 "No timer is running." と応答する。
- **誤起動対策**: L2はセッション中のみ+タイマー操作系以外の語は無視(オープン辞書にしない)。テレビ音声対策として、2秒以上の連続発話に埋め込まれた単語コマンドは無視(単独発話のみ受理)。
- **TV/家族の声**: v1では話者識別はしない(過剰設計)。誤記録は「取り消し」1語で直せることを担保する方が費用対効果が高い。
- **無音タイムアウト**: L2で40分間コマンドなし→「タイマーは続いています」と1回だけ通知(音声ではなくローカル通知)。授乳の寝落ちは正常系として扱う(タイマー放置の自動クローズは90分、平均+3σより長く)。
- **電話着信/他アプリの音声**: オーディオセッション割込み時はリスニング一時停止→復帰後に自動再開+ハプティクス。
- **イヤホン(AirPods等)**: 接続時は応答をイヤホンのみに出す(部屋のスピーカーから出さない)。マイクもイヤホン優先。
- **多言語環境**: アプリ言語と認識言語は独立して設定可(日本在住外国人家庭)。

## ナイトモード音声仕様

- 22:00〜6:00(設定可): TTS音量を「小声プリセット」に自動切替、応答文を最短形に(「右、スタート」→「右」)。
- 「静かに」モード時のハプティクス言語: 開始=1回 / 停止=2回 / エラー=3回短振動。

## 音声UXの計測(Layers/グロース実験と接続)

- 記録のうち音声経由の割合 / コマンド認識成功率 / 「取り消し」率 / L2セッション平均長を計測。
- 認識成功率 <90% のコマンドは辞書を改善(同義語追加)する運用ループを回す。
