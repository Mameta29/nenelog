# 07. マネタイズ設計 — RevenueCat + HAMM戦略

> HAMM賞の審査観点=「最も堅牢で創造的なマネタイズ戦略」。2025年1位は「収益の50倍を低所得地区に還元」のVector Guard。単純サブスクでは勝てないので、**「睡眠不足の親への誠実さ」を収益戦略として設計する**。

- 無料トライアル: 年額プランに14日(新生児期の1日は長い。7日では価値を体感しきれない)。

## 「誠実さを収益戦略にする」— HAMM提出文の核

1. **深夜誤課金の構造的防止**: ペイウォールの購入ボタンは0時〜5時は長押し必須+確認を1枚挟む(「寝ぼけタップで課金させないペイウォール」— おそらく世界初の主張。審査で確実に目を引く)。
2. **授乳期が終わったら引き止めない**: 記録が30日途絶えたら「卒業おめでとう」画面から1タップで解約導線+全データ無料エクスポート。LTVを削る設計に見えるが、口コミ・再入園(第二子)・信頼を買っている。
3. **アクセシビリティ無償**: VoiceOver/TalkBack利用が検出された場合、音声L2/L3を無償開放(申請不要)。Peace Prize との一貫性。
4. **Pay it forward**: 収益の5%を産後ケア団体に寄付+NICU卒業児家庭・多胎児家庭への無償コード配布プログラム(申請フォーム)。
5. **ギフトサブスク**(P1, Stripe Funnel): 祖父母・友人が出産祝いとして年額を贈れるWebファネル。「出産祝いに現金より気が利くもの」という新しい購入文脈を作る = Funnel Vision賞と接続。

## RevenueCat 実装

- purchases-kmp v3.5.0 + `purchases-kmp-ui`(Paywalls を CMP 上で表示)。
- Products: `premium_monthly` / `premium_annual`(trial 14d) / `premium_lifetime`、Entitlement: `premium`、Offering: `default`(+Layers実験用 `experiment_a`)。
- Paywall はRevenueCatダッシュボードのリモート編集を活かし、審査提出後も文言を最適化。
- 審査員用: 3ストア分のプロモコード+Devpost記載。RevenueCat sandbox でトライアル動作確認。
- Web(P1): RevenueCat Billing + Stripe。アプリ内entitlementとWeb購入の突合を確認(同一Supabase authユーザーにひも付け)。
