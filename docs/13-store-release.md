# 13. ストアリリース — 3ストア申請・審査リスク対策・ASO

## 最重要リスク: Google Play 新規個人アカウントのテスト要件

- 2023年11月以降に作成された**個人**デベロッパーアカウントは、製品版公開前に**クローズドテスト(一定数のテスター×14日間連続)**が必須(2025年に必要テスター数は緩和されたが14日間は不変)。
- **今日やること**: mameta の Play Console アカウントの作成日・種別を確認。
  - 旧アカウント or 組織アカウント → このリスクは消える。
  - 新規個人アカウントの場合 → **逆算: 9/30製品版公開には遅くとも9/8にクローズドテスト開始が必要** → Android の実装計画をこれに合わせる(`12-schedule.md` に反映済み)。テスターは Shipaton Discord・じゃけえフォロワー・家族で集める。
- Apple は既存の Developer Program 加入状況を確認(未加入なら今週中に、D-U-N-S不要の個人で)。

## 審査リスクと対策(否認されやすいポイントを先回り)

| リスク | 対策 |
|---|---|
| マイク常時使用の疑い(iOS背景audio) | 用途文言を具体化+審査ノートに「セッション中のみ・録音の保存/送信なし・オンデバイス認識」と実演動画URLを添付 |
| 医療アプリ扱い(健康助言) | 記録専用であることをメタデータで明確化。授乳量の推奨・診断的表現を一切書かない(`01` 非スコープ) |
| 子ども向けアプリ誤分類 | 対象は保護者(17歳+設定不要だが、Kids カテゴリにしない)。Play のターゲットオーディエンス申告は「大人」 |
| IAP審査(トライアル・価格表示) | 価格・更新条件・解約方法をペイウォールに明記(景表法/ストア規約両対応) |
| データセーフティ/プライバシーラベル | 音声: 収集しない(端末内処理)。記録データ: アプリ機能のため収集・暗号化。ラベルと実装の一致をリリース前に監査 |
| プライバシーポリシー | `web/` にホスト(日英)。Supabase・RevenueCat・OneSignal・Sentry・(P1: Claude API)をサブプロセッサとして列挙 |
