# 11. #BuildInPublic 計画 — じゃけえ(@jakeee_ai)で発信する

> 賞金最大$30K・唯一「実装力と独立に努力で勝率を上げられる」賞。8月中に開始しないと積み上がらない。
> **2025年受賞者の発信分析は `research/bip-winner-analysis.md`(必読)。本計画はその勝ちパターンに基づく。**

## 基本方針: 「開発は最速、物語は反復」

- 開発を演出のために遅らせない(締切リスク)。その代わり、**毎晩の実戦テストで自然に発生する反復ループを物語の単位にする**。
- 審査されるのは完成度ではなく journey。「今日これ作った」ではなく「**なぜ・誰の一言で・どう変えたか**」を見せる(受賞者3人の共通点)。

## 最強の資産: 「嫁テスト」ループ

Echo Reminder(2位)は見知らぬ人とのユーザーテストで刺さった。我々はそれを**家庭内で毎晩**回せる:

```
昼: 機能実装(Claude Code併走) → 夜: 妻が本物の授乳で実戦投入
→ 翌朝: フィードバックを1行で記録 → 昼: 改善 → 夜: 再テスト → 投稿
```

- 投稿フォーマット: 「Day X: 昨夜の授乳テストで『小声だと認識しない』と言われた→今日、小声モードを実装した(動画)」— **失敗→指摘→改善差分**を1ポストで完結させる。
- 妻は「ユーザー#1」として物語に登場させる(顔・名前は出さない。「うちの一番厳しいレビュアー」)。Tomo型の「誰から・何を・どう変えた」を家庭内で実現する構図。
- 実際に想定されるネタの種: 深夜の音量問題、寝ぼけた発話の認識率、抱っこ中に言いやすい/言いにくいコマンド、「ごちそうさま」で止めたい等 → 実装前から `05-voice-ux.md` にある仕様も、**あえて妻の指摘を起点に直した過程として見せられるものは見せる**(事実の順序を偽らない範囲で、テスト→改善の因果を丁寧に記録する)。

- 中心物語: 「子育て以外なんでも自動化してきたパパが、ついに“子育ての記録”を自動化するアプリを、**妻と赤ちゃんに毎晩テストされながら**2ヶ月でリリースする」

- 運用基盤: `~/dev/sns/x-auto-account/`。**Shipaton関連ポストは自動生成でも最終確認は人間**(審査員が見る前提)。

## 型(受賞者パターンの直輸入)

1. **Day X 形式で毎日1本**(Echo型)。動画優先: 実機で声→アプリが答える瞬間、失敗テイク、妻テストの録音(声はテキスト化でも可)。
2. **数字の定期公開**(Gurwi型): 事前登録→DL→課金→**音声経由の記録率**・コマンド認識成功率(このアプリ固有の数字は珍しくて強い)。週1のStats投稿+リリース後は毎日。
3. **長文振り返り**(Tomo型): 週1でハイライトをピン留めスレッドに追記+Zenn記事(mameta名義)→英訳をdev.toへ(JetBrains賞のコミュニティ貢献加点と兼用)。
4. **意見募集とお礼**: 初週から「どんなコマンドで止めたい?」等を募集し、採用したら名前付き(ハンドル)で感謝(Tomo型)。
5. **失敗の正直な報告**: リジェクト・バグ・効果がなかった施策(Echo が TikTok ブースト不発を報告したように)。リジェクトが来たら Gurwi 型に「Help me @RevenueCat」でネタ化。

## 審査員に届くための英語戦略(最重要)

1. **主要マイルストーンは英日バイリンガル**(英語本文+日本語リプ or セルフ引用翻訳)。Day X 投稿は最低でも英語字幕付き動画。
2. ハッシュタグ: **`#Shipaton` が主タグ(公式ルール原文: "Posts should be tagged #Shipaton and may also be tagged #BuildInPublic")**。`#BuildInPublic` は任意の追加(リーチ用に付けてよい)。Shipaton Discord の #post-engagement-boost にも共有。
3. **週1でベスト投稿をピン留めスレッドに追記** → **Devpost 提出フォームへの投稿リンク記載が審査対象になる公式条件**("submit links to the publicly visible posts on their Devpost submission form")。ピン留めスレッドがそのまま提出物になる。審査員が2分で全体を追える導線として維持する。

## キックオフ投稿: 「嫁からの発注LINE」(Day 1 の型)

- 起点は**妻との実際のLINEやり取りのスクショ**: 「最近AIハマっとるらしいじゃん。じゃあアプリ作ってよ」→「おっぱいのますとき両手塞がっとるから右と左でタイマー入れ替えるの大変なんよ。なんか**声だけでいい感じでできるやつ**」のような流れ。
- **必ず本物のやり取りにする**(今晩実際にLINEで聞く。妻の不満は実在するので捏造の必要がない。台本より本人の言葉・方言・雑さの方が面白い)。捏造スクショは嘘松判定+審査での致命傷リスク。
- 「声だけでいい感じでできるやつ」(妻の実際の言い回しに置換)を**プロダクトの北極星フレーズ**として以後の投稿・総括で回収し続ける。
- 同じ投稿内で「作ります。9月にリリースします」と宣言し Day 1 として起点化。リプで英訳(会話形式のまま)+タグ。
- **ブックエンド**: リリース日に同じLINEスレッドで「できたよ」→ 妻の実使用レビューを投稿し、Day 1 の伏線を回収。総括スレッド冒頭にも使う。
- 継続フォーマット: 毎晩の嫁テストのフィードバックも LINE スクショ(または同トーンの引用)で統一し、Day X 動画と併用してシリーズの視覚的一貫性を作る。
- 事前に妻の同意を取る(スクショ公開+2ヶ月間「ユーザー#1」として登場し続けること)。アイコン・名前・無関係な会話はトリミング。
