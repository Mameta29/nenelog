# #BuildInPublic 受賞者の発信分析(Shipaton 2025・mameta提供 2026-08-15)

> X検索のサンプリング(期間分割+ハッシュタグ/Day形式/アプリ名/数字キーワードの組合せ)による再構築。全件ダンプではないが主要シリーズはカバー。

## 1. Echo Reminder(@KatoLuca)— 2位【最も審査向きの型】

- 「Day X」形式の短め動画をほぼ毎日投稿。実機操作・ユーザーテスト・失敗・改善をそのまま見せる。
- Day 3-10: UI構築・バグ発見・**irlユーザーテスト**・「Let me know any features you'd like to see!」と初期から意見募集
- Day 16-25: テストの学び反映、通知・設定・リピート対応、「subtle design changes go a long way… but take time」と地味な改善を可視化。ロゴ案募集・YouTube開設
- Day 26-41: App Store提出→リリース、大バグ+ウィジェット完成、RevenueCat連携、ペイウォールA/B、**見知らぬ人との再ユーザーテスト**(カレンダービュー要望多数と共有)、**TikTokブーストが効果薄だったと正直に報告**。Day 41で締め
- **勝因**: 「失敗→テスト→改善」ループの明確さ+動画で実際の操作・テストの瞬間を見せたこと

## 2. Tomo Japan(@tammyho52)— 3位【個人ストーリー+フィードバック明示型】

- Day XX形式+Medium長文を並行。金融→独学iOSのキャリア転換を織り交ぜる
- 「Prioritizing App Store submission = relentlessly cut to true MVP」とスコープ管理を公開
- ペイウォール遅延修正を「my fault 🙈」と自虐しつつ改善報告
- **勝因**: フィードバックを「**誰から・何を・どう変えた**」と具体的に書く。個人的制約(新職・通勤開発)を隠さない

## 3. Gurwi(@camilopenalver)— 1位【数字透明性+社会的ストーリー型】

- 詳細Stats投稿を定期的に(ユーザー数・MRR・国別・獲得チャネル)
- Appleリジェクトも「Help me @RevenueCat」とネタ化
- 14,000→15,000ユーザー、初の$1,000収益、$1,000 MRR を順次報告。総括で 3M+ビュー・16K+ユーザー・トップ5教育アプリ・4.9★を列挙
- **勝因**: 数字の徹底公開+成長のプレッシャーを隠さない+コミュニティ(TikTok/IG)との関係性

## 4. MemoLune(@AmiOtsuka_SE)— Buzziest Launch 3位(参考・日本語)

- 日本語中心のカジュアル実況。環境構築の失敗談(mainブランチ1本でバグ多発)を正直に共有。イベント連動(PyCon JP)で話題作り

## 共通パターン(→ 我々の発信設計への示唆)

1. **失敗・詰まり・フィードバック・改善差分を隠さない。**「今日これ作りました」ではなく「なぜ・どう変えたか」
2. 媒体は 動画(Echo)× 数字(Gurwi)× 長文振り返り(Tomo)の組合せが最強
3. 審査基準対応: 透明性/ストーリー・エンゲージメント(意見募集・名前付き感謝)・学習と反復の可視化
4. Day X 形式のシリーズ感が追いやすさを作る
